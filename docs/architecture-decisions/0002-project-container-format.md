# ADR 0002: `.cncrender` 프로젝트 컨테이너 형식

- 상태: 승인
- 날짜: 2026-07-26
- 스키마 성숙도: M1 구현 전 잠정 식별자

## 맥락

CNC Render 프로젝트는 JSON 도메인 데이터뿐 아니라 G-code 원문, 머신·공구·재료 자산, 재료 제거 체크포인트와 선택적 미리보기를 포함할 수 있다. 단일 JSON은 대형 바이너리에 부적합하고, 브라우저 로컬 저장 구조인 OPFS·IndexedDB를 그대로 내보내면 이식성과 버전 관리가 어렵다.

기술 백서 v1.0의 프로젝트 확장자는 제품명과 일치하도록 정정되어야 한다. Codex 작업 하네스 M0는 확장자, schema ID와 MIME 초안을 하나로 통일하도록 요구한다.

## 결정 요약

| 항목 | 결정 |
|---|---|
| 파일 확장자 | `.cncrender` |
| 미디어 타입 | `application/vnd.cnc-render.project+zip` |
| 컨테이너 | ZIP |
| 루트 문서 | `project.json` |
| 스키마 식별자 | `urn:cnc-render:schema:project:1` |
| 현재 스키마 버전 | 정수 `1` |
| 문자 인코딩 | JSON과 경로 이름은 UTF-8 |

`urn:cnc-render:schema:project:1`은 M1에서 실제 JSON Schema를 발행하기 전의 **잠정 식별자**다. M1은 이 문자열을 `$id`로 예약해 사용한다. 호환되지 않는 구조 변경은 이 식별자를 같은 의미로 재사용하지 않고 `schemaVersion`과 URN의 마지막 버전을 함께 올린다.

승인 이전의 프로젝트 확장자는 읽기·쓰기 형식으로 채택하지 않는다. 별도 레거시 형식이 실제로 배포되기 전까지 자동 호환을 만들지 않는다.

## 컨테이너 구조

버전 1 컨테이너의 최소 구조는 다음과 같다.

```text
example.cncrender
├── project.json                 # 필수: 프로젝트와 엔트리 목록
├── programs/                    # 선택: G-code 원문
│   └── <program-id>.nc
├── assets/                      # 선택: 머신·공구·재료·CAD 자산
│   └── <sha256>.<ext>
├── checkpoints/                 # 선택: 압축된 simulation 체크포인트
│   └── <checkpoint-id>.bin
└── previews/                    # 선택: 사용자 확인용 비권위 미리보기
    └── thumbnail.webp
```

디렉터리 엔트리 자체는 필수가 아니다. 모든 파일 엔트리는 `project.json`에 경로, 역할, 미디어 타입, 바이트 길이와 SHA-256 해시를 선언한다. 선언되지 않은 파일은 버전 1 가져오기에서 사용하지 않는다.

`project.json`은 프로젝트의 권위 있는 루트 문서이며 최소한 다음 값을 포함한다.

```json
{
  "$schema": "urn:cnc-render:schema:project:1",
  "schemaVersion": 1,
  "id": "00000000-0000-4000-8000-000000000000",
  "name": "Example project",
  "unitSystem": "metric",
  "resources": [
    {
      "path": "programs/main.nc",
      "role": "gcode-program",
      "mediaType": "text/x-gcode",
      "byteLength": 128,
      "sha256": "<64 lowercase hexadecimal characters>"
    }
  ]
}
```

위 예시는 컨테이너 식별을 위한 최소 계약이지 전체 `ProjectSchema`가 아니다. 기계, 소재, 공구, 공정, 설정과 참조 무결성의 전체 스키마는 M1에서 정의한다.

## 버전과 호환성

1. `schemaVersion`은 문자열이 아닌 양의 정수이며 버전 1 파일에서는 정확히 `1`이다.
2. `$schema`는 버전 1에서 `urn:cnc-render:schema:project:1`이어야 한다.
3. 지원 버전보다 새로운 파일은 추측해 열지 않고 읽기 불가 이유를 표시한다.
4. 마이그레이션은 순차적이고 결정론적인 순수 변환으로 구현한다. 가져온 원본은 덮어쓰지 않으며, 저장할 때 새 `.cncrender` 사본을 만든다.
5. 알 수 없는 선택 자원 역할은 실행하지 않고 무시할 수 있다. 프로젝트 의미에 필수인 알 수 없는 필드·역할은 실패로 처리한다.
6. 체크포인트는 재생성 가능한 캐시다. 체크포인트 코어 버전이나 설정이 맞지 않으면 폐기하고 권위 있는 프로젝트·G-code로 다시 계산한다.
7. 화면 미리보기, 파생 메시와 보고서는 권위 있는 계산 결과가 아니며 프로젝트 의미 해시에 포함할지 여부를 역할별로 명시한다.

## ZIP 프로파일

- 버전 1 writer는 일반 단일 디스크 ZIP을 생성하고 `STORE` 또는 `DEFLATE` 압축만 사용한다.
- 암호화 ZIP, 분할 ZIP, 자기 추출 실행 파일과 다중 디스크 ZIP은 지원하지 않는다.
- 엔트리 이름은 UTF-8, `/` 구분자, 상대 경로만 허용한다.
- export 시 엔트리를 정규화된 경로의 사전순으로 기록하고 JSON 키 정렬·숫자 직렬화·압축 설정을 고정한다.
- 의미 해시는 ZIP의 타임스탬프나 압축 바이트가 아니라 정규화된 `project.json`과 권위 있는 자원의 경로·해시로 계산한다.
- OPFS와 IndexedDB의 내부 레이아웃은 ZIP 레이아웃의 공개 계약이 아니다. storage 어댑터가 import/export 시 변환한다.

## 가져오기 보안 원칙

프로젝트는 신뢰할 수 없는 입력으로 취급하며 임의 디렉터리에 바로 압축 해제하지 않는다.

### 1. 다중 형식 검증

- 사용자 선택 단계에서 `.cncrender` 확장자를 확인한다.
- 브라우저나 서버가 MIME을 제공하면 `application/vnd.cnc-render.project+zip`과 일치하는지 확인한다. 운영체제가 MIME을 제공하지 않는 경우 비어 있다는 이유만으로 거부하지 않는다.
- ZIP 매직 바이트, 중앙 디렉터리와 CRC를 검사한다.
- 루트 `project.json`, `$schema`, `schemaVersion`과 JSON Schema를 검사한다.
- 확장자나 MIME만 믿지 않으며, 내부 검증 실패를 경고로 낮추지 않는다.

### 2. 경로 안전성

다음 엔트리는 압축 해제 전에 거부한다.

- 절대 경로, 드라이브 문자, UNC 경로
- `..`, 빈 경로 세그먼트, NUL 또는 제어 문자를 포함한 경로
- `\` 구분자나 정규화 후 컨테이너 루트를 벗어나는 경로
- 심볼릭 링크, 하드 링크, 장치 파일과 기타 비정규 파일
- Unicode 정규화 또는 대소문자 무시 비교에서 충돌하는 중복 경로

검증된 엔트리도 가져오기 전용 임시 OPFS 영역에 스트리밍한 뒤 원자적으로 채택한다.

### 3. 자원 한도와 압축 폭탄 방어

- 엔트리 수, 엔트리별·전체 압축 크기와 압축 해제 크기, 압축률, 경로 길이와 JSON 중첩 깊이에 하드 한도를 둔다.
- 한도는 성능 티어별로 낮아질 수 있지만 가져오기 도중 자동으로 늘리지 않는다.
- 중앙 디렉터리의 선언값만 신뢰하지 않고 스트리밍 중 실제 해제 바이트를 다시 센다.
- 중첩 ZIP은 자동으로 재귀 해제하지 않는다.
- 전체 파일을 한 번에 JavaScript 메모리로 읽지 않는다.

구체적인 기본 한도는 실제 fixture와 브라우저 메모리 예산을 측정해 M8에서 계약으로 고정한다. 한도를 정하기 전에도 **무제한 가져오기**는 허용하지 않는다.

### 4. 내용과 무결성 검증

- `project.json`에 선언된 `byteLength`와 SHA-256을 각 자원 스트림과 대조한다.
- 선언되지 않은 엔트리, 누락된 필수 엔트리, 중복 ID와 끊어진 참조를 거부한다.
- JSON 숫자의 `NaN`, `Infinity`, 범위를 벗어난 값과 단위 없는 물리량을 스키마 계층에서 거부한다.
- G-code, CAD, HTML, SVG와 텍스트 자산은 모두 데이터로만 처리한다. `eval`, 동적 module import, 셸 명령, 매크로 스크립트 또는 임의 URL을 실행하지 않는다.
- 프로젝트 안의 WASM, JavaScript, 실행 파일과 플러그인은 로드하거나 실행하지 않는다.
- 외부 URL 참조와 자동 원격 가져오기는 버전 1에서 허용하지 않는다. 자원은 컨테이너에 포함되고 해시로 참조되어야 한다.
- 사용자 제공 이름과 진단 문자열은 DOM에 삽입할 때 텍스트로 렌더링한다. HTML로 신뢰하지 않는다.

### 5. 실패와 복구

- 검증 또는 마이그레이션이 실패하면 현재 열린 프로젝트와 기존 자동 저장을 변경하지 않는다.
- 부분 import는 사용자 프로젝트 목록에 노출하지 않고 임시 영역을 정리한다.
- 오류는 실패 단계와 안전한 수정 방법을 설명하되, 로컬 절대 경로나 원문 전체 같은 민감 정보를 보고서에 자동 포함하지 않는다.
- 클라우드 저장소는 `.cncrender` 객체를 불투명 데이터로 취급하고, 서버에서도 크기·MIME·해시·권한을 재검증한다.

## 내보내기와 전송

- 다운로드 응답은 `Content-Type: application/vnd.cnc-render.project+zip`을 사용한다.
- 파일명은 안전하게 정규화하고 `.cncrender`를 한 번만 붙인다.
- export는 임시 파일을 완성하고 해시 검증을 마친 뒤 사용자 대상 파일로 원자적으로 승격한다.
- 같은 의미의 입력·버전·설정·시드는 같은 의미 해시를 만들어야 한다.
- 프로젝트 공유는 기본 비공개이며 예측 불가능한 ID와 권한 검사를 사용한다.
- 이 형식은 실제 CNC 장비로 전송하는 실행 패키지가 아니다. 포함된 G-code에는 시뮬레이션의 정확도 등급과 교육용 한계를 유지한다.

## 결과

### 이점

- JSON 스키마와 대형 바이너리 청크를 하나의 이식 가능한 파일로 전달할 수 있다.
- 브라우저에서 널리 지원되는 ZIP 도구와 스트리밍 방식을 사용할 수 있다.
- 자원별 해시와 명시적 버전으로 증분 저장, 무결성 확인과 마이그레이션이 가능하다.
- 런타임 OPFS·IndexedDB 구조를 공개 파일 계약에서 분리할 수 있다.

### 비용과 제약

- ZIP bomb, 경로 순회, 중복 경로와 손상 엔트리에 대한 별도 방어가 필요하다.
- 일부 자원은 이미 압축되어 ZIP 압축 이점이 작다.
- 전체 파일을 수정할 때 컨테이너 재작성 비용이 발생할 수 있어 런타임 자동 저장은 OPFS 체크포인트를 우선한다.

## 채택하지 않은 대안

- **단일 JSON**: 대형 메시·체크포인트의 base64 비용과 메모리 사용 때문에 채택하지 않는다.
- **OPFS 디렉터리 그대로 내보내기**: 브라우저 구현 세부와 공개 계약이 결합하므로 채택하지 않는다.
- **새 전용 바이너리 컨테이너**: 초기 구현·감사·복구 도구 비용이 크므로 채택하지 않는다.
- **승인 이전 확장자**: 제품명과 승인된 저장 규칙에 맞지 않아 채택하지 않는다.
