# CNC Render 디자인 백서 (Design Whitepaper)

**버전**: 1.0  
**작성일**: 2026년 7월 26일  
**작성자**: Bryan  
**프로젝트 상태**: UI/UX 설계 및 프로토타입 정의 단계  
**참고 문서**: CNC Render 기술 백서 v1.0, 웹 프로젝트용 디자인 백서 템플릿 v1.0, 추후 작성 예정인 콘텐츠 명세서·QA 하네스·접근성 점검표  
**프로젝트 명**: CNC Render — Web CNC Machining Simulator & Learning Lab

> CNC Render의 인터페이스는 기존 산업용 CAD/CAM 소프트웨어의 복잡한 패널 구조를 그대로 복제하지 않습니다. 3D 가공 장면을 제품의 중심으로 두고, 현재 작업에 필요한 제어와 수치만 단계적으로 노출하는 정밀 도구형 UI를 지향합니다. 디자인은 라이트모드로 고정하며, 장식성 애니메이션·네온·블러·과도한 그림자·입체적인 스킨을 배제하여 시각적 피로와 GPU 사용량을 동시에 줄입니다.

---

## 1. 프로젝트 개요 (Project Overview)

### 1.1. 프로젝트 명

**CNC Render UI/UX Design**  
부제: **Minimal Interface for Interactive CNC Simulation**

### 1.2. 목적 (Purpose)

CNC Render는 실제 CNC 장비를 접하기 어려운 사용자가 밀링, 선반, 3+2축, 동시 5축 가공을 웹에서 학습하고 실험할 수 있도록 하는 시뮬레이션 플랫폼입니다. UI는 전문 가공 정보를 숨기지 않으면서도 초심자가 길을 잃지 않게 해야 하며, 동시에 브라우저의 그래픽 자원을 3D 시뮬레이션에 최대한 배정해야 합니다.

본 디자인의 핵심 목표는 다음과 같습니다.

1. **3D 우선 구조**: 화면에서 가장 중요한 것은 패널이 아니라 공작물, 공구, 기계 축, 공구 경로와 재료 제거 결과입니다. 데스크톱 작업 화면의 60% 이상을 기본적으로 3D 뷰포트에 배정합니다.
2. **복잡성의 단계적 공개**: 입문자는 현재 튜토리얼 단계에 필요한 값만 보고, 숙련자는 전체 공정·G-code·기계 파라미터에 접근하도록 모드와 컨텍스트에 따라 정보 밀도를 조정합니다.
3. **수치 가독성 확보**: mm, rpm, mm/rev, mm/tooth, m/min, N, N·m, kW, ° 등의 값이 빠르게 비교되도록 숫자 폭, 소수점 자리, 단위 표기, 열 정렬 규칙을 통일합니다.
4. **낮은 시각·그래픽 비용**: CSS 효과가 3D 렌더링과 메인 스레드를 경쟁하지 않도록 블러, 대형 그림자, 연속 애니메이션, 복잡한 SVG 필터, 반투명 레이어 중첩을 금지합니다.
5. **산업용이지만 비산업적인 외형**: 공작기계의 물리적 무게감은 3D 모델 안에서 표현하고, 웹 인터페이스는 Google·Apple 계열의 명료한 정보 설계와 현대적인 중립성을 따릅니다.
6. **학습과 전문 도구의 공존**: 튜토리얼 모드에서는 설명과 행동 유도가 우선이며, 샌드박스·G-code Lab에서는 작업 효율과 진단 정보가 우선입니다.

### 1.3. 핵심 차별점 (Key Differentiators)

1. **Quiet Precision — 조용한 정밀성**  
   외형적 장식을 통해 전문성을 표현하지 않습니다. 정렬, 간격, 타이포그래피, 단위 체계, 상태 표현의 일관성이 정밀 도구의 신뢰감을 만듭니다.

2. **Contextual Density — 문맥 기반 정보 밀도**  
   모든 패널을 항상 열어 두지 않고, 선택한 기계·공구·공정·튜토리얼 단계와 관련된 제어만 노출합니다. 동일한 데이터도 입문·표준·고급 보기에서 표현 밀도를 다르게 합니다.

3. **Render-Budgeted UI — 렌더링 예산을 보존하는 UI**  
   UI는 독립적인 시각적 과시가 아니라 3D 시뮬레이션을 보조하는 계층입니다. 브라우저 프레임 예산, DOM 수, 리렌더 빈도, 차트 갱신률, 폰트·아이콘 용량까지 디자인 기준에 포함합니다.

### 1.4. 디자인 원칙 (Design Principles)

#### 원칙 1. 3D 장면이 항상 첫 번째입니다

- 툴바, 패널, 안내문은 3D 장면을 가리지 않는 위치에 배치합니다.
- 화면 중앙에 대형 모달을 자주 띄우지 않습니다.
- 시뮬레이션 중 변경 가능한 항목과 변경할 수 없는 항목을 명확히 구분합니다.
- 긴 설명은 뷰포트 위가 아니라 튜토리얼 패널 또는 별도 학습 페이지에 둡니다.

#### 원칙 2. 한 화면에는 하나의 주된 행동만 강조합니다

- 튜토리얼에서는 `다음 단계`, 샌드박스에서는 `시뮬레이션 실행`, 오류 상황에서는 `문제 위치로 이동`이 주 액션입니다.
- 동일한 시각적 강도를 가진 주요 버튼을 여러 개 배치하지 않습니다.
- 삭제, 초기화, 비상정지 등 위험 동작은 색상과 위치를 분리하되 과도하게 크게 만들지 않습니다.

#### 원칙 3. 수치는 장식이 아니라 구조로 읽히게 합니다

- 숫자에는 탭형 숫자(tabular figures)를 적용합니다.
- 동일 종류의 값은 동일한 소수점 자릿수를 사용합니다.
- 값과 단위를 시각적으로 분리하되, 단위가 입력 필드 밖으로 멀리 떨어지지 않게 합니다.
- 범위, 권장값, 현재값, 한계값은 한 줄에서 비교할 수 있게 배치합니다.

#### 원칙 4. 상태는 색상 하나에 의존하지 않습니다

- 성공, 주의, 경고, 충돌은 색상과 함께 아이콘, 레이블, 패턴, 문구를 사용합니다.
- 3D 객체의 경고 표시는 외곽선, 위치 마커, 진단 목록과 연결합니다.
- 빨강과 초록만으로 정상·오류를 구분하지 않습니다.

#### 원칙 5. 움직임은 가공 시뮬레이션에만 사용합니다

- 버튼 리플, 카드 부상, 아이콘 회전, 네온 점멸, 배경 패럴랙스는 사용하지 않습니다.
- CSS 전환은 상태 이해에 필요한 경우에만 80~120ms 이내로 제한하거나 즉시 전환합니다.
- 사용자가 집중해야 하는 움직임은 공구, 축, 공작물, 공구 경로와 재료 제거입니다.

### 1.5. 명시적 비목표 (Design Non-goals)

CNC Render는 다음 스타일을 지향하지 않습니다.

- CATIA V5, 구형 Mastercam, 구형 HMI를 연상시키는 회색 그라데이션·입체 버튼·과도한 패널 분할
- 검정 배경, 형광 청록, 네온 라인으로 구성된 전형적인 “하이테크” 콘셉트
- 공업 기계를 표현한다는 이유로 녹, 스크래치, 철판 텍스처, 경고 테이프를 UI 배경에 사용하는 방식
- 카드마다 큰 그림자와 둥근 모서리를 적용한 소비자용 대시보드 스타일
- CSS가 거의 없는 표와 직사각형 입력창만 나열한 원시적인 엔지니어링 도구 스타일
- 모든 기능을 하나의 화면에 고정 배치하는 패널 과밀 구조
- 실제 기계 조작반을 픽셀 단위로 재현한 스큐어모피즘

## 2. 상세 기능 요구사항 (Detailed Requirements)

### 2.1. 레이아웃 및 인터페이스 (Layout & Interface)

#### 뷰 모드 정책

- **기본 전략**: Desktop First + Fluid Workspace
- **주요 작업 기준 해상도**: 1440×900 이상
- **최소 전체 편집 해상도**: 1280×720
- **태블릿**: 튜토리얼·뷰어·간단한 파라미터 조정 중심
- **모바일**: 학습 콘텐츠, 결과 검토, 공구 경로 재생, 프로젝트 열람 중심

#### 데스크톱 기본 작업실

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ Global Command Bar · 48px                                                    │
├──────────────┬────────────────────────────────────────────┬──────────────────┤
│ Context Rail │                                            │ Inspector        │
│ 240~280px    │              3D Viewport                   │ 304~336px        │
│              │              Flexible                      │                  │
│              │                                            │                  │
├──────────────┴────────────────────────────────────────────┴──────────────────┤
│ Bottom Dock: Timeline / G-code / Diagnostics / Metrics · 36~280px           │
└──────────────────────────────────────────────────────────────────────────────┘
```

- **Global Command Bar**: 프로젝트명, 실행 상태, 실행·일시정지·정지, 저장 상태, 모드 전환, 도움말을 배치합니다.
- **Context Rail**: 튜토리얼 단계, 프로젝트 트리, 공구·재료 라이브러리 중 현재 작업에 필요한 하나의 문맥만 표시합니다.
- **3D Viewport**: 중앙의 가변 영역이며 최소 560px 너비를 보장합니다.
- **Inspector**: 현재 선택한 객체나 공정의 속성을 표시합니다. 선택이 없을 때는 프로젝트 요약 또는 빈 상태를 표시합니다.
- **Bottom Dock**: 기본적으로 축소 상태이며, 타임라인·G-code·진단·그래프가 필요할 때 확장합니다.

#### 공간 배분 원칙

- 1440px 이상에서는 3D 뷰포트가 전체 콘텐츠 면적의 최소 60%를 차지해야 합니다.
- 양쪽 패널이 동시에 열린 상태에서도 뷰포트 너비가 720px 미만이 되면 한쪽 패널을 자동 접습니다.
- 패널은 사용자가 220~420px 범위에서 조절할 수 있으나, 마지막 상태를 프로젝트가 아닌 개인 UI 설정으로 저장합니다.
- 패널 내부에 또 다른 고정 사이드바를 만들지 않습니다.
- 하나의 기능을 위해 3중 이상의 중첩 패널을 사용하지 않습니다.

#### 화면 크기별 정책

| 뷰포트 | 레이아웃 | 지원 범위 |
|---|---|---|
| 1600px 이상 | 좌·중앙·우 3열 + 하단 도크 | 전체 샌드박스, 5축, G-code Lab |
| 1280~1599px | 3열 압축 또는 한쪽 패널 자동 접기 | 전체 편집, 고급 그래프 선택 표시 |
| 1024~1279px | 중앙 + 단일 문맥 패널 | 튜토리얼, 3축·선반 편집, 제한된 5축 |
| 768~1023px | 뷰포트 + 하단 시트 | 튜토리얼, 재생, 측정, 기본 값 변경 |
| 767px 이하 | 단일 열 | 학습, 프로젝트 요약, 결과·경고 검토 |

#### 테마 정책

- **라이트모드만 지원합니다.**
- 시스템 테마 설정을 자동 반영하지 않습니다.
- 고정된 밝은 배경 위에서 3D 장면과 데이터 가독성을 검증합니다.
- 야간 사용을 위한 별도 다크 테마 대신 브라우저·운영체제 밝기 조절과 저휘도 디스플레이 설정을 안내합니다.
- 기술 백서 v1.0과 동일하게 **라이트모드 전용** 정책을 적용합니다.

#### 페이지 배경 구조

- 애플리케이션 배경: 연한 쿨 그레이
- 패널·도크: 흰색
- 입력 영역·보조 섹션: 매우 옅은 회색
- 3D 뷰포트: 공작물의 실루엣이 분명히 보이는 중립적인 밝은 회색 또는 사용자가 선택한 제한된 스튜디오 배경
- 그라데이션 배경과 배경 이미지 금지

### 2.2. 사용자 상호작용 (Interaction Logic)

#### 상호작용 기본 원칙

- 사용자는 한 번 클릭하여 선택하고, 두 번 클릭하여 상세 편집으로 진입하지 않습니다. 이중 클릭 의존성은 최소화합니다.
- 선택 상태는 테두리, 행 배경, 3D 외곽선으로 즉시 표시합니다.
- 모든 변경은 가능하면 인라인으로 수행하며, 모달은 파일 가져오기, 파괴적 확인, 복합 마법사에 한정합니다.
- 드래그가 가능한 요소에는 명확한 핸들 또는 커서가 있어야 합니다.
- 기능을 숨기기 위한 아이콘만 있는 버튼은 툴팁과 접근 가능한 이름을 제공합니다.

#### Hover 및 Click 정책

장식적인 호버·클릭 효과는 사용하지 않습니다.

- 금지: 확대, 이동, 카드 부상, 그림자 증가, 글로우, 네온, 리플, 탄성, 회전, 색상 파동
- 허용: 기능적 식별을 위한 즉시 적용되는 1단계 배경색 변화, 밑줄, 테두리 변화
- 전환 시간은 기본 `0ms`; 상태 구분이 어려운 컴포넌트에만 최대 `100ms`
- 활성화된 버튼은 눌린 깊이를 흉내 내지 않고 배경·테두리·아이콘 상태로 표시합니다.
- 링크는 본문에서 밑줄을 기본 적용하여 호버에 의존하지 않습니다.

#### 포커스 정책

- 키보드 포커스는 2px 외곽선과 2px 간격으로 표시합니다.
- 포커스 링은 그림자 효과가 아니라 `outline`을 사용합니다.
- 3D 뷰포트 포커스 시 현재 키보드 조작 범위를 짧은 상태 문구로 표시합니다.
- 모달과 팝오버는 포커스 트랩과 ESC 닫기를 지원합니다.

#### 입력 방식

1. **UnitInput**
   - 숫자 입력과 단위를 하나의 제어로 묶습니다.
   - 값, 단위, 증가·감소 스텝, 최소·최대, 권장 범위를 제공합니다.
   - 마우스 휠로 값이 우발적으로 변경되지 않도록 기본 비활성화합니다.
   - 소수점, 음수, 지수 표기 허용 여부를 속성별로 제한합니다.

2. **Segmented Control**
   - 2~4개의 상호 배타적 선택에만 사용합니다.
   - 지나치게 둥근 캡슐 형태가 아니라 6px 반경의 연결형 버튼을 사용합니다.

3. **Select / Combobox**
   - 공구·재료·기계처럼 항목 수가 많은 경우 검색 가능한 콤보박스를 사용합니다.
   - 최근 사용, 호환 가능, 전체 항목을 구분합니다.

4. **Slider**
   - 시뮬레이션 속도, 투명도, 단면 위치처럼 연속 미리보기가 필요한 항목에만 사용합니다.
   - 정확한 값 입력이 필요한 절삭 파라미터에는 반드시 숫자 입력을 병행합니다.

5. **Toggle / Checkbox**
   - 즉시 적용되는 이진 상태는 토글, 여러 항목 선택은 체크박스를 사용합니다.
   - `냉각수 표시`, `공구 경로 표시`처럼 시각화 옵션에 적합합니다.

6. **G-code Editor**
   - 코드 편집은 Monaco Editor를 사용하되 미니맵, 장식성 애니메이션, 불필요한 인라인 위젯은 기본 비활성화합니다.
   - 현재 실행 줄, 오류 줄, 브레이크포인트를 서로 다른 모양과 색상으로 구분합니다.

#### 시뮬레이션 재생 제어

- 기본 제어: 처음으로, 이전 이벤트, 재생/일시정지, 다음 이벤트, 정지
- 속도: 0.1×, 0.25×, 0.5×, 1×, 2×, 5×, 10×, 25×, 50×, 100×
- 재생 버튼은 화면 상단과 타임라인에 중복 배치하지 않습니다. 상단은 주 제어, 타임라인은 세부 스크럽을 담당합니다.
- 실행 중 수정할 수 없는 값은 비활성화하고 비활성 사유를 툴팁 또는 보조 문구로 표시합니다.
- 비상정지는 빨간색 텍스트 버튼 또는 경계가 분명한 소형 제어로 제공하되, 일반 `정지`와 의미를 구분합니다.

#### 3D 뷰포트 조작

- 좌클릭: 객체 선택
- 우클릭 드래그 또는 설정 가능한 제스처: Orbit
- 가운데 버튼 드래그: Pan
- 휠: Zoom
- `F`: 선택 객체에 맞추기
- 숫자키 또는 뷰 큐브: Front, Top, Right, Isometric
- `Esc`: 현재 측정·선택·조작 취소
- 조작 방식은 첫 실행 시 한 번만 간단한 오버레이로 안내하며, 지속적인 도움말 배너를 띄우지 않습니다.

### 2.3. 데이터 구조 및 모듈 (Component Structure)

#### 1. Global Command Bar

- 높이: 48px
- 좌측: 로고, 프로젝트명, 저장 상태
- 중앙: 현재 모드(Tutorial / Sandbox / G-code Lab), 실행 상태
- 우측: 실행 제어, 품질 프리셋, 도움말, 사용자 메뉴
- 로고는 24px 이하의 단색 심볼과 워드마크를 사용합니다.
- 메뉴 수가 많아지면 더보기 메뉴로 이동하되, 실행·저장·모드 전환은 숨기지 않습니다.

#### 2. Context Rail

모드에 따라 다음 중 하나를 표시합니다.

- Tutorial Stepper
- Project Tree
- Machine / Tool / Material Library
- Operation List

동일 화면에 네 개를 모두 탭으로 나열하지 않고 사용 흐름에 맞춰 대표 문맥을 선택합니다. 다른 문맥은 상단의 작은 전환 메뉴 또는 명령 팔레트에서 엽니다.

#### 3. Machine Viewport

- UI 전체의 핵심 컴포넌트입니다.
- 상단 좌측: 현재 뷰 이름, 좌표계, 단위
- 상단 우측: 카메라, 단면, 측정, 표시 옵션
- 하단 좌측: 축 좌표 또는 선택 객체 요약
- 하단 우측: 성능 티어, FPS는 고급 모드에서만 표시
- 오버레이는 최대 네 모서리로 제한하며 중앙 영역을 비워 둡니다.
- 모든 오버레이는 3D 캔버스와 별도 DOM 레이어로 구현합니다.

#### 4. Inspector

Inspector는 선택한 항목의 유형에 따라 섹션이 변경됩니다.

- Machine: 축 한계, 작업 영역, 스핀들, 테이블
- Tool: 직경, 날 수, 돌출 길이, 홀더, 최대 RPM
- Material: 재질, 경도, 추천 절삭 조건, 시각 재질
- Operation: 공정 유형, 절입, 스텝오버, 이송, RPM
- Diagnostic: 원인, 위치, 영향, 수정 제안

섹션은 `Summary`, `Geometry`, `Cutting`, `Limits`, `Advanced` 순으로 구성합니다. 고급 항목은 접힌 상태가 기본입니다.

#### 5. Bottom Dock

- 기본 축소 높이: 36px
- 표준 확장 높이: 220px
- 최대 높이: 뷰포트의 45%
- 탭: Timeline, G-code, Diagnostics, Metrics
- 오류 발생 시 Diagnostics 탭에 배지만 표시하고 사용자의 현재 탭을 강제로 변경하지 않습니다. Critical 충돌만 자동 열림을 허용합니다.

#### 6. Tutorial Panel

- 현재 목표
- 필요한 조작
- 왜 이 작업을 수행하는지
- 성공 조건
- 힌트
- 다음 단계

한 단계에는 하나의 주된 목표만 둡니다. 본문 설명은 5~8줄 이내로 유지하고, 상세 이론은 `자세히 보기`에서 별도 학습 문서로 연결합니다.

#### 7. Asset Library

- 검색, 필터, 정렬을 상단 한 줄에 배치합니다.
- 카드보다 목록·행 구조를 기본으로 합니다.
- 공구 실루엣, 이름, 직경, 길이, 재질, 호환 여부를 한 행에 표시합니다.
- 큰 썸네일 격자는 교육용 탐색 화면에서만 사용합니다.

#### 8. Diagnostic Panel

- 심각도
- 문제 유형
- 발생 시점
- G-code 줄
- 관련 축·공구·부품
- 원인
- 수정 방법
- 3D 위치로 이동

진단 메시지는 “문제–원인–조치” 순서로 작성합니다. 오류 코드만 단독으로 노출하지 않습니다.

#### 9. Measurement Overlay

- 거리, 직경, 반경, 각도, 깊이, 벽 두께, 형상 편차
- 측정값은 뷰포트에 간단히 표시하고 전체 목록은 Inspector 또는 Bottom Dock에 둡니다.
- 치수선은 1px, 텍스트 배경은 불투명한 흰색을 사용해 3D 모델과 겹쳐도 읽히게 합니다.

#### 10. Report View

- 프로젝트·기계·재료·공구 요약
- 사이클 타임
- 최대·평균 편차
- 과절삭·미절삭
- 충돌·경고
- 부하·동력·공구 마모 근사
- 주요 스크린샷

리포트는 인쇄 가능한 흰색 문서형 레이아웃을 사용하며 작업실 UI를 그대로 캡처하지 않습니다.

### 2.4. 핵심 화면 정의 (Key Screens)

#### A. Home / Learning Hub

- 제품 소개보다 `학습 시작`, `샌드박스 열기`, `G-code 불러오기`를 먼저 제시합니다.
- 최근 프로젝트와 진행 중 튜토리얼을 최대 4개만 표시합니다.

- 정적인 고품질 렌더 또는 가벼운 캔버스 프리뷰만 허용합니다.

- 난이도, 기계 종류, 가공 방식, 예상 시간으로 필터링합니다.

- 왼쪽에 단계 안내, 중앙에 뷰포트, 오른쪽에 현재 단계에 필요한 입력만 표시합니다.

#### D. Sandbox Workspace

- 프로젝트 트리, 뷰포트, Inspector, Bottom Dock의 전체 구조를 사용합니다.

- 설정 완료 후에는 마법사를 닫고 동일 정보를 일반 패널에서 수정할 수 있습니다.

#### E. G-code Lab

- 기본 비율은 코드 38%, 3D 62% 또는 사용자가 조절 가능한 분할입니다.
- 현재 실행 줄과 3D 위치, 타임라인 이벤트가 서로 연결됩니다.
- 오류는 코드 에디터 밑줄, 진단 목록, 뷰포트 마커 세 곳에서 동일 ID로 연결합니다.

- 목표 모델과 결과 모델을 Overlay, Split, Heatmap으로 비교합니다.
- 색상 범례를 항상 표시합니다.
- 최대·평균·분위수 편차를 구분합니다.
- 결과가 교육용 근사임을 하단 고지로 명확히 표시합니다.

### 2.5. 출력 및 결과물 (Output)

#### 결과물 형식

- React + TypeScript 기반 웹 UI
- CSS Variables + CSS Modules 기반 디자인 시스템
- Storybook 컴포넌트 카탈로그
- Figma 원본 및 컴포넌트 라이브러리
- SVG 아이콘 세트
- 반응형 화면 명세
- 인쇄용 PDF 리포트 스타일
- 시각 회귀 테스트 기준 이미지

#### 품질 기준 (QA Standards)

1. **접근성**: WCAG 2.2 AA를 목표로 합니다.
2. **반응형**: 정의된 해상도에서 의도하지 않은 가로 스크롤이 없어야 합니다.
3. **가독성**: 작업실 본문과 입력값은 12px 미만으로 내려가지 않습니다.
4. **대비**: 일반 텍스트 4.5:1 이상, 큰 텍스트·UI 경계 3:1 이상을 유지합니다.
5. **수치 안정성**: 값 변경 시 열 너비가 흔들리지 않아야 합니다.
6. **상태 일관성**: 동일한 심각도와 동작은 모든 화면에서 같은 색·아이콘·문구 규칙을 사용합니다.
7. **프레임 예산**: UI 애니메이션이나 차트 때문에 3D 시뮬레이션 프레임이 눈에 띄게 감소하지 않아야 합니다.
8. **키보드 조작**: 파일 업로드를 제외한 핵심 흐름은 키보드로 수행할 수 있어야 합니다.
9. **오류 복구**: 잘못된 수치 입력은 값 손실 없이 수정 가능해야 합니다.
10. **시각 회귀**: 주요 화면과 컴포넌트 상태를 Playwright 기반 스냅샷으로 검증합니다.

## 3. 기술 스택 및 라이브러리 (Tech Stack)

### 3.1. Core

- **Frontend Framework**: React 19 + TypeScript
- **Build Tool**: Vite
- **Styling Engine**: CSS Variables + CSS Modules
- **State Management**: Zustand의 UI 전용 슬라이스
- **3D Layer**: Three.js WebGPU/WebGL 2 렌더러
- **Code Editor**: Monaco Editor
- **Component Documentation**: Storybook

#### 스타일링 엔진 선정 이유

Tailwind CSS나 런타임 CSS-in-JS가 반드시 성능 문제를 일으키는 것은 아니지만, CNC Render는 디자인 토큰, 상태, 패널 밀도, 수치 정렬 규칙을 장기간 엄격하게 유지해야 합니다. 따라서 다음 구조를 기본으로 합니다.

- 전역 토큰: CSS Custom Properties
- 컴포넌트 범위 스타일: CSS Modules
- 동적 값: 제한된 인라인 CSS 변수
- 복잡한 조건부 스타일: `data-state`, `data-severity`, `aria-*` 속성
- 3D 시각화 색상: TypeScript 토큰과 WGSL/GLSL 상수로 동기화

### 3.2. Libraries & Tools

1. **React Aria Components**
   - **용도**: 키보드, 포커스, 스크린리더를 지원하는 접근성 기반 UI 프리미티브
   - **설정**: 시각 스타일과 전환 효과는 전부 CNC Render 토큰으로 재정의

2. **Floating UI**
   - **용도**: 툴팁, 팝오버, 콤보박스 위치 계산
   - **설정**: 화면 밖으로 나가지 않는 자동 배치만 사용하며 등장 애니메이션은 사용하지 않음

3. **Lucide Icons 또는 자체 SVG 아이콘 세트**
   - **용도**: 범용 UI 아이콘
   - **설정**: 기본 16px, stroke 1.75px, 라운드 캡, 단색 사용
   - **주의**: CNC 전용 아이콘은 자체 제작하며 아이콘 폰트는 사용하지 않음

4. **Monaco Editor**
   - **용도**: G-code 편집, 구문 강조, 진단, 현재 실행 줄 표시
   - **설정**: 미니맵 비활성화, 애니메이션 스크롤 비활성화, 코드 렌즈 제한, Worker 지연 로드

5. **TanStack Virtual**
   - **용도**: 수백~수천 개 공구·진단·G-code 이벤트 목록 가상화
   - **설정**: 실제 행 높이 고정 또는 측정 캐시 사용

6. **Recharts 미사용 원칙 / 경량 차트 계층**
   - **용도**: 부하, 토크, 동력, 온도, 축 위치 그래프
   - **방식**: Canvas 또는 직접 작성한 경량 SVG 차트 사용
   - **이유**: 시뮬레이션 중 고빈도 데이터 업데이트와 번들·DOM 비용 절감

7. **Storybook + axe-core**
   - **용도**: 컴포넌트 상태 문서화, 접근성 자동 검사

8. **Playwright**
   - **용도**: 반응형·키보드·시각 회귀·핵심 흐름 E2E 검사

9. **Figma Variables / Tokens Studio 선택 사용**
   - **용도**: 디자인 토큰 관리 및 코드 토큰과의 동기화
   - **원칙**: Figma 전용 값이 코드에 수동 복제되지 않도록 JSON 토큰을 단일 출처로 관리

### 3.3. 라이브러리 제한 정책

- 애니메이션 전용 라이브러리를 추가하지 않습니다.
- UI 전체를 특정 대형 디자인 프레임워크의 기본 테마에 의존하지 않습니다.
- 아이콘 폰트, CSS 필터 기반 아이콘 변형, Lottie 애니메이션을 사용하지 않습니다.
- 차트 라이브러리는 프로토타입에서만 평가하고, 실시간 작업실에는 경량 구현을 우선합니다.
- 외부 웹폰트 CDN에 의존하지 않고 자체 호스팅과 서브셋을 사용합니다.

- **Level 5 — Label**: 12px / 18px / 500, 입력 라벨·메타데이터
- **Level 6 — Numeric / Code**: 13px / 20px / 450, 수치·G-code·축 좌표
- **Level 7 — Caption**: 11px / 16px / 450, 제한적으로 사용하며 핵심 정보에는 사용 금지

:root {

#### 계층 표현 방식

1. 크기보다 **굵기와 여백**으로 섹션을 구분합니다.
2. 패널 제목에 불필요한 배경 막대를 사용하지 않습니다.
3. 구분선은 1px 중립색을 사용하고, 모든 박스를 테두리로 감싸지 않습니다.
4. 핵심 값은 큰 숫자로 과장하지 않고 13~18px 범위에서 정렬과 대비로 강조합니다.
5. 경고는 전체 패널을 빨갛게 만들지 않고, 좌측 인디케이터·아이콘·제목·관련 값에만 상태색을 적용합니다.

### 4.2. 정보 밀도 구조 (Information Density)

#### 세 가지 표시 밀도

1. **Guided**
   - 튜토리얼 기본값
   - 현재 단계에 필요한 항목만 표시
   - 권장값과 설명을 함께 제공
   - 고급 탭 숨김

2. **Standard**
   - 샌드박스 기본값
   - 주요 절삭·기하·기계 값을 표시
   - 섹션별 접기 지원
   - 설명은 툴팁 또는 보조 문구로 축소

3. **Expert**
   - 세부 축, 공구 보정, 물성, 검증 옵션 표시
   - 표 형태와 복수 열 입력 허용
   - 성능 HUD와 원시 진단 데이터 접근

표시 밀도는 프로젝트 데이터가 아니라 사용자 UI 설정으로 저장합니다. Guided에서 숨겨진 값도 시스템 기본값으로 명시되어야 하며, 사용자 몰래 임의 계산하지 않습니다.

### 4.3. 반응형 로직 (Responsive Logic)

#### Desktop: 1600px 이상

- 좌측 Rail과 우측 Inspector를 동시에 표시합니다.
- Bottom Dock을 최대 280px까지 확장할 수 있습니다.
- Tool Library와 Inspector 간 드래그 앤 드롭을 지원합니다.

#### Compact Desktop: 1280~1599px

- 패널 너비를 축소합니다.
- Context Rail과 Inspector 중 최근 사용하지 않은 패널을 자동 접을 수 있습니다.
- Global Command Bar의 보조 항목은 더보기 메뉴로 이동합니다.

#### Small Desktop / Large Tablet: 1024~1279px

- 한 번에 한 개의 보조 패널만 표시합니다.
- Inspector는 우측 오버레이가 아니라 레이아웃 열로 유지해 뷰포트를 가리지 않습니다.
- Bottom Dock은 최대 화면 높이의 38%로 제한합니다.

#### Tablet: 768~1023px

- 3D 뷰포트를 상단, 문맥 패널을 하단 시트로 배치합니다.
- G-code 전체 편집보다 읽기·현재 줄 확인을 우선합니다.
- 세밀한 드래그보다 단계형 버튼과 숫자 입력을 사용합니다.

#### Mobile: 767px 이하

- 전체 CNC 편집 기능을 억지로 축소하지 않습니다.
- 튜토리얼 본문, 프로젝트 상태, 시뮬레이션 재생, 결과 리포트, 진단 목록을 제공합니다.
- 3D는 단일 손가락 회전, 두 손가락 확대·이동을 지원하는 뷰어 모드입니다.
- 고정밀 재료 제거·다중 패널·G-code 대량 편집은 지원 범위 밖임을 명확히 표시합니다.

### 4.4. 핵심 컴포넌트 로직 (Core Components)

#### A. Button

- 높이: 32px 기본, 36px 주요 액션, 28px 도구형 버튼
- 반경: 6px
- 종류: Primary, Secondary, Quiet, Danger
- 한 화면의 Primary 버튼은 원칙적으로 하나
- 아이콘 전용 버튼은 32×32px 이상
- 로딩 중 레이아웃 너비가 변하지 않게 함
- 비활성 상태는 불투명도만 낮추지 않고 배경·텍스트·커서를 함께 변경

#### B. UnitInput

- 라벨은 입력 위에 배치
- 입력값은 우측 정렬
- 단위 영역은 고정 폭
- 권장 범위는 하단 보조 문구 또는 한계 마커로 표시
- 오류 시 입력 테두리, 오류 아이콘, 설명 문구를 동시에 표시
- 소수점 정밀도는 속성 스키마에서 정의

#### C. ParameterRow

```text
[Label]              [  1250.0 ][rpm]
Recommended          900–1600 rpm
```

- Inspector의 기본 정보 단위입니다.
- 라벨과 값을 같은 행에 두되 보조 설명은 다음 행에 둡니다.
- 긴 라벨은 생략 부호보다 2줄을 허용합니다.

#### D. DataTable

- 헤더 높이: 32px
- 행 높이: 36px 기본, 44px 설명 포함
- 숫자는 우측 정렬, 텍스트는 좌측 정렬
- 단위를 열 제목 또는 별도 단위 열에 일관되게 표시
- 소수점 위치가 맞도록 탭형 숫자 사용
- 줄무늬 배경 대신 1px 행 구분선 사용
- 선택 행은 옅은 파란색 배경과 좌측 2px 표시선 사용

#### E. Tabs

- 하단 도크·Inspector 대분류에만 사용합니다.
- 탭 수는 최대 5개입니다.
- 활성 탭은 하단 2px 선과 텍스트 굵기로 표시합니다.
- 캡슐형 탭과 슬라이딩 애니메이션을 사용하지 않습니다.

#### F. Accordion

- Inspector의 고급 섹션에 사용합니다.
- 펼침 상태를 프로젝트 또는 객체 유형별로 기억할 수 있습니다.
- 전체 섹션을 모두 접어 정보가 사라지지 않도록 Summary는 항상 펼침 상태입니다.

#### G. Toast

- 성공 메시지는 자동 저장 등 사용자가 확인할 필요가 없는 상태에 한해 3초 후 사라집니다.
- 오류·충돌은 Toast만으로 전달하지 않고 Diagnostic Panel에 영구 기록합니다.
- 한 번에 최대 3개, 우측 하단 또는 상단 명령바 아래에 표시합니다.
- 등장·퇴장 애니메이션은 사용하지 않거나 단순 불투명도 80ms로 제한합니다.

#### H. Dialog

- 파일 가져오기, 프로젝트 삭제, 단위 체계 변경, 머신 교체처럼 영향 범위가 큰 작업에 사용합니다.
- 최대 너비 560px, 복합 설정은 760px
- 배경 블러 금지, 불투명 오버레이 사용
- 확인 버튼과 취소 버튼 순서를 전 제품에서 통일합니다.

#### I. Command Palette

- `Ctrl/Cmd + K`
- 공구, 재료, 기계, 명령, 튜토리얼, 설정 검색
- 최근 명령과 현재 문맥 명령을 우선 표시
- 단축키를 학습할 수 있게 결과 우측에 키 조합 표시

#### J. SimulationTimeline

- 공정 구간, 공구 교환, 경고, 충돌, 체크포인트를 서로 다른 마커 모양으로 표시합니다.
- 마커 밀도가 높을 때 클러스터링합니다.
- 타임라인 자체에 과도한 색을 사용하지 않고 선택·경고·충돌만 강조합니다.
- 드래그 중에는 저정밀 프리뷰, 놓은 후 정밀 상태 복원을 사용합니다.

#### K. DiagnosticItem

- 심각도 아이콘
- 한 줄 제목
- 시간 또는 코드 줄
- 관련 객체
- 해결 행동
- 펼치면 원인과 기술 상세

Critical 항목만 빨간색 배경을 사용하되 옅은 색으로 제한합니다. Warning은 노란 배경 전체보다 좌측 색상 표시선과 아이콘을 우선합니다.

### 4.5. 상태 및 데이터 동기화

- 시뮬레이션은 초당 60회 이상 갱신될 수 있지만, 일반 수치 UI는 10Hz를 기본으로 갱신합니다.
- 축 좌표처럼 사용자가 연속 변화를 관찰해야 하는 값은 20Hz까지 허용합니다.
- 차트는 기본 10Hz, 고급 성능 모드 20Hz를 상한으로 합니다.
- React 상태에는 대용량 시뮬레이션 배열을 넣지 않고 요약값과 선택 상태만 저장합니다.
- 동일 값이 변하지 않았으면 컴포넌트를 다시 렌더링하지 않습니다.
- 사용자가 입력 중인 값은 시뮬레이션 피드백으로 덮어쓰지 않습니다.

### 4.6. 빈 상태·로딩·오류 상태

#### 빈 상태

- 일러스트 대신 단순 아이콘, 제목, 한 줄 설명, 하나의 행동 버튼을 사용합니다.
- 예: “선택된 공구가 없습니다. 공구 라이브러리에서 공구를 추가하십시오.”

#### 로딩 상태

- 대형 Skeleton shimmer는 사용하지 않습니다.
- 고정된 회색 블록 또는 단순 진행 표시를 사용합니다.
- 3D 자산 로딩은 항목명, 단계, 진행률, 취소 가능 여부를 표시합니다.
- 500ms 미만 작업에는 로딩 UI를 띄우지 않아 깜빡임을 방지합니다.

#### 오류 상태

- 데이터 손실 여부를 먼저 알립니다.
- 복구 가능한 행동을 우선 표시합니다.
- 기술 로그는 접힌 상세 영역에 둡니다.
- WebGPU 미지원처럼 환경 문제인 경우 지원되는 대체 모드를 즉시 제시합니다.

### 5.2. 타이포그래피 (Typography)

#### Font Family

- **UI / Korean / Latin**: `Pretendard Variable`
- **G-code / 좌표 / 기술 로그**: `JetBrains Mono`
- **Fallback**: `-apple-system`, `BlinkMacSystemFont`, `Segoe UI`, `Noto Sans KR`, `sans-serif`
- **Monospace Fallback**: `Cascadia Mono`, `Consolas`, `monospace`

#### Font Weight

- Regular 400: 본문, 입력값
- Medium 500: 라벨, 탭, 보조 강조
- SemiBold 600: 제목, 주요 버튼
- Bold 700: 마케팅 헤드라인 또는 Critical 숫자에만 제한

#### 숫자·단위 규칙

- 모든 수치 테이블과 입력값에 `tabular-nums` 적용
- `0`과 `O`가 혼동되는 코드 영역에는 slashed zero 사용
- 음수 부호는 하이픈과 구분되는 유니코드 마이너스 기호 사용을 검토
- 기본 소수점:
  - 좌표·길이: 3자리
  - 각도: 2자리
  - RPM: 정수
  - 이송·절삭속도: 1~3자리, 속성별 정의
  - 힘·토크·동력: 1~2자리
- 단위는 값을 반복하지 않는 범위에서 열 헤더 또는 입력 접미사로 표시
- 천 단위 구분은 긴 값에만 사용하며 G-code 원문에는 적용하지 않음

### 5.3. 간격 및 그리드 (Spacing & Grid)

- 기본 단위: 4px
- 토큰: 4, 8, 12, 16, 20, 24, 32, 40, 48
- 작업실 패널 내부 패딩: 12px 또는 16px
- 페이지형 콘텐츠 최대 너비: 1120px
- 본문 읽기 영역 최대 너비: 760px
- Inspector 섹션 간격: 20px
- 입력 필드 간 세로 간격: 12px
- 라벨과 입력 간격: 6px
- 아이콘과 텍스트 간격: 6~8px

8px만을 절대 규칙으로 사용하지 않고 4px 단위로 정밀하게 조절하되, 임의의 5px·7px·13px 값은 만들지 않습니다.

### 5.4. 모서리와 경계 (Radius & Borders)

- 입력·버튼: 6px
- 패널·작은 카드: 8px
- 대화상자: 10px
- 태그·상태 배지: 999px 허용
- 작업실 전체를 지나치게 둥글게 만들지 않습니다.
- 기본 테두리: 1px solid `--border-subtle`
- 활성 입력: 1px `--primary-600` + focus outline
- 대형 패널 사이에는 그림자보다 배경 차이와 구분선을 사용합니다.

### 5.5. 그림자 및 투명도 (Elevation)

- 작업실의 상시 패널에는 `box-shadow`를 사용하지 않습니다.
- 팝오버·대화상자에만 제한된 그림자를 사용합니다.
- `backdrop-filter`, `filter: blur()`, 다중 그림자 금지
- 반투명 표면을 여러 겹 중첩하지 않습니다.
- 뷰포트 위 수치 라벨은 가독성을 위해 92~96% 불투명 흰색 배경을 허용합니다.

```css
.popover {
  background: var(--surface-primary);
  border: 1px solid var(--border-subtle);
  box-shadow: 0 10px 30px rgb(24 32 44 / 12%);
}
```

### 5.6. 아이콘 (Iconography)

- 기본 크기: 16px
- 주요 도구: 18px
- 빈 상태: 최대 32px
- 선 굵기: 1.75px
- 단색 SVG, `currentColor` 사용
- 채워진 아이콘은 경고·선택 등 제한된 상태에만 사용
- 기계·공구 아이콘은 실제 실루엣을 단순화하되 16px에서도 구분 가능해야 함
- 의미가 불분명한 공업용 약어 아이콘은 텍스트와 함께 사용
- 이모지와 3D 아이콘 사용 금지

### 5.7. 데이터 시각화 (Data Visualization)

#### 기본 원칙

- 그래프는 장식이 아니라 의사결정과 오류 탐지를 위한 도구입니다.
- 축, 단위, 범례, 현재값을 항상 제공합니다.
- 배경 그리드는 주선만 남기고 보조선은 최소화합니다.
- 영역 그래프 그라데이션을 사용하지 않습니다.
- 실시간 그래프는 최대 4개 시리즈를 권장합니다.
- 색상뿐 아니라 선 종류, 마커, 직접 라벨을 병행합니다.

#### 권장 차트

- Line: 축 위치, 부하, 동력, 온도
- Area: MRR 누적 또는 잔여 재료량 한 개 시리즈
- Bar: 공정별 시간, 공구별 사용량
- Heatmap: 형상 편차, 열, 잔삭
- Gauge 미사용: RPM·부하는 숫자+범위 막대로 표시
- 3D 원형 게이지, 자동차 계기판형 UI 금지

### 5.8. 모션 (Motion)

- 기본적으로 장식성 모션은 없습니다.
- 패널 열기·닫기는 즉시 또는 최대 100ms 선형 전환
- 스크롤은 사용자의 입력을 따르며 강제 스무스 스크롤 금지
- 로딩 스피너는 1초 이상 작업에만 사용
- 충돌 경고 점멸 금지
- `prefers-reduced-motion`에서는 모든 비필수 전환을 0ms로 설정
- 공구와 기계 축의 움직임은 물리 시간에 맞추며 UI 모션 토큰과 분리

### 5.9. 문구 및 용어 (Content Design)

- 기능명은 한국어를 기본으로 하고, 필요한 경우 영어 전문 용어를 괄호에 병기합니다.
- 같은 개념에 `이송`, `피드`, `Feed`를 혼용하지 않습니다.
- 버튼은 명사보다 동사형을 사용합니다: `공구 추가`, `시뮬레이션 실행`, `결과 비교`
- 오류는 사용자를 비난하지 않습니다.
- 권장값과 한계값을 구분합니다.
- “안전함”, “완벽함”, “실기계와 동일함”과 같은 보증성 표현을 사용하지 않습니다.

## 7. 개발 시 주의사항 (Implementation Notes)

### 7.1. 스타일링 전략 (Styling Strategy)

1. **토큰 우선**
   - 색, 간격, 글꼴, 크기, 반경을 하드코딩하지 않습니다.
   - 예외값은 코드 리뷰에서 근거를 남깁니다.

2. **낮은 선택자 복잡도**
   - CSS 선택자는 최대 3단계를 권장합니다.
   - `!important`는 접근성 유틸리티와 외부 컴포넌트 오버라이드 외에 사용하지 않습니다.

3. **CSS 효과 제한**
   - `backdrop-filter`, 큰 blur, 다중 shadow, 장시간 animation 금지
   - 레이아웃 전환에 `transform: scale()` 사용 금지
   - 패널 크기 조절 시 전체 DOM에 연속 transition을 걸지 않음

4. **전역 스타일 최소화**
   - Reset, Typography, Body, Focus 규칙만 전역으로 둡니다.
   - 컴포넌트 상태는 CSS Modules에서 관리합니다.

5. **인쇄 스타일 분리**
   - 결과 리포트는 `print.css`를 사용하여 작업실 UI와 분리합니다.

### 7.2. UI 성능 예산 (UI Performance Budget)

CNC Render의 GPU와 메인 스레드 예산은 3D 시뮬레이션을 우선합니다. UI는 다음 기준을 지향합니다.

| 항목 | 기준 |
|---|---|
| UI JavaScript + Style + Paint | 일반 프레임 평균 4ms 이하 |
| CSS 애니메이션 | 지속 실행 0개 원칙 |
| 보이는 DOM 노드 | 작업실 기본 2,000개 이하 권장 |
| 차트 갱신률 | 기본 10Hz, 최대 20Hz |
| 수치 HUD 갱신률 | 10~20Hz |
| 폰트 초기 전송량 | WOFF2 합산 400KB 이하 권장 |
| 초기 UI CSS | gzip 80KB 이하 권장 |
| 아이콘 | 개별 SVG 또는 스프라이트, 필요 항목만 포함 |
| 상시 그림자 레이어 | 0개 |
| Backdrop blur | 0개 |

#### 구현 지침

- 시뮬레이션 매 프레임마다 React 트리를 갱신하지 않습니다.
- 긴 목록은 가상화합니다.
- 패널이 닫혀 있을 때 내부 차트와 편집기를 일시 중지하거나 언마운트합니다.
- Monaco Editor는 G-code Lab 진입 시 지연 로드합니다.
- 홈 화면의 3D 프리뷰는 정식 시뮬레이션 렌더러와 별도 경량 프리셋을 사용합니다.
- 뷰포트 위 UI는 CSS 3D 변환을 사용하지 않습니다.
- CSS 애니메이션이 없더라도 빈번한 상태 업데이트로 레이아웃 스래싱이 발생하지 않게 합니다.
- `ResizeObserver`, `IntersectionObserver` 콜백은 배치 처리합니다.

### 7.3. 접근성 가이드 (Accessibility)

1. 모든 상호작용 요소는 키보드로 접근할 수 있어야 합니다.
2. 포커스 순서는 화면의 시각적 순서와 일치해야 합니다.
3. 아이콘 버튼은 `aria-label` 또는 보이는 텍스트를 가져야 합니다.
4. 입력 오류는 `aria-describedby`로 설명과 연결합니다.
5. 상태색은 아이콘, 문구, 모양과 함께 사용합니다.
6. 3D 뷰포트에는 현재 선택 객체, 좌표, 실행 상태, 주요 경고를 텍스트로 제공하는 접근성 요약 영역을 둡니다.
7. 충돌 위치는 3D 마커뿐 아니라 진단 목록과 G-code 줄로 접근할 수 있어야 합니다.
8. 그래프는 표 또는 요약 텍스트를 대체 표현으로 제공합니다.
9. 단축키는 사용자 입력 필드와 충돌하지 않으며 설정에서 확인·변경할 수 있어야 합니다.
10. 모션 감소 설정에서는 비필수 전환을 제거하고 시뮬레이션 속도는 자동 변경하지 않습니다.
11. 화면 확대 200%에서 핵심 기능이 손실되지 않아야 합니다.
12. Windows 고대비 모드에서 선택·포커스·오류 경계가 유지되어야 합니다.

### 7.4. 수치·단위 가독성

- 입력값의 자릿수 증가로 레이아웃이 밀리지 않도록 최소 폭을 설정합니다.
- 음수, 매우 큰 값, 과학적 표기, `NaN`, `Infinity`의 예외 표시를 정의합니다.
- `0.000`과 값 없음 `—`을 구분합니다.
- 단위 변환 시 원본 정밀도를 유지하고 표시 반올림과 내부 값을 분리합니다.
- 권장 범위와 기계 한계 범위를 시각적으로 구분합니다.
- 표에서 단위가 행마다 반복되지 않도록 하되, 화면 일부만 캡처해도 단위를 알 수 있게 열 헤더를 고정합니다.
- 각도는 `°`, 회전수는 `rpm`, 시간은 `hh:mm:ss` 또는 `ms`를 문맥에 맞게 사용합니다.

### 7.5. 3D 뷰포트와 UI 충돌 방지

- UI 포인터 이벤트 영역을 명확히 정의해 패널 조작이 카메라 조작으로 전달되지 않게 합니다.
- 뷰포트 단축키는 뷰포트에 포커스가 있을 때만 활성화합니다.
- 팝오버가 3D 위에 열릴 때 카메라 드래그를 일시 중지합니다.
- 3D 선택 외곽선은 색상과 두께가 UI 포커스 링과 혼동되지 않게 합니다.
- 캔버스 해상도 변경과 패널 리사이즈는 디바운스하고, 드래그 중에는 저비용 프리뷰를 사용합니다.
- 뷰포트 배경을 완전 흰색으로 두지 않아 흰색 재료·기계 부품의 실루엣이 사라지지 않게 합니다.

### 7.6. 예외 처리 (Exception Handling)

1. **WebGPU 미지원**
   - 기능이 사라졌다는 메시지 대신 WebGL 2 모드에서 가능한 기능과 제한을 표시합니다.

2. **성능 저하**
   - FPS 경고를 지속적으로 띄우지 않고 품질 자동 조정 결과를 상태 영역에 표시합니다.
   - 사용자가 품질을 다시 올릴 수 있게 합니다.

3. **패널 공간 부족**
   - 글자와 입력을 무조건 축소하지 않고 패널 접기 또는 단일 패널 모드로 전환합니다.

4. **긴 이름과 다국어**
   - 공구명·재료명은 한 줄 생략과 전체 툴팁을 사용합니다.
   - 한국어·영어에서 버튼 너비가 달라지는 것을 고려합니다.

5. **데이터 로딩 실패**
   - Skeleton 애니메이션 대신 고정 Placeholder와 재시도 행동을 제공합니다.

6. **저장 충돌**
   - 로컬과 클라우드 버전을 시간·변경 요약과 함께 비교합니다.

7. **지원하지 않는 G-code**
   - 줄 번호, 코드, 지원 수준, 대체 가능 여부를 표시합니다.

## 8. 화면별 디자인 명세 (Screen Specifications)

### 8.1. Workspace 기본 상태

- 상단 48px 명령바
- 좌측 260px Project Tree
- 중앙 가변 Viewport
- 우측 320px Inspector
- 하단 36px 축소 Dock
- 3D 장면 배경 `#E9EDF1` 계열
- 선택이 없으면 Inspector에 프로젝트·기계 요약 표시
- 시작 시 Performance HUD 숨김

### 8.2. 시뮬레이션 실행 상태

- 실행 버튼이 일시정지 버튼으로 변경
- 편집 불가 입력 비활성화
- 상단에 실행 시간과 현재 공정명 표시
- 축 좌표 20Hz 갱신
- Diagnostic 배지만 갱신하며 오류가 없으면 숫자 `0`을 표시하지 않음
- 충돌 시 시뮬레이션 정지, 관련 객체 외곽선, 진단 항목, 코드 줄 연결

### 8.3. 튜토리얼 성공 상태

- 화면 전체 축하 애니메이션 금지
- Tutorial Panel 안에 성공 아이콘, 결과 요약, 다음 단계 버튼 표시
- 뷰포트는 마지막 결과를 그대로 유지
- 성공음은 선택 설정이며 기본적으로 짧고 낮은 음량

### 8.4. G-code 오류 상태

- 코드 줄에 오류 밑줄
- Diagnostic Panel에 문제와 해결 방법
- Inspector에 지원 코드 또는 파라미터 정보
- 같은 오류를 Toast로 중복 표시하지 않음

### 8.5. 결과 비교 상태

- 중앙 뷰포트에 목표/결과 비교
- 우측에 편차 범례와 통계
- 하단에 공정별 결과 표
- Overlay, Split, Heatmap 전환은 Segmented Control 사용
- Heatmap 색 범위와 단위를 명확히 표시

## 9. 디자인 시스템 운영 (Design Governance)

### 9.1. 단일 출처

- `design/tokens/cnc-render.tokens.json`을 디자인 토큰의 단일 출처로 사용합니다.
- Figma와 코드가 동일 토큰을 읽도록 자동화합니다.
- 색상·간격 변경은 컴포넌트 개별 수정이 아니라 토큰 변경과 영향 검토를 거칩니다.

### 9.2. 컴포넌트 승인 단계

1. Wireframe
2. 접근성 상태 정의
3. 시각 디자인
4. Storybook 구현
5. 키보드·스크린리더 검사
6. 성능 검사
7. 시각 회귀 기준 등록
8. 제품 화면 적용

### 9.3. 변경 원칙

- 새 컴포넌트를 만들기 전 기존 컴포넌트 조합으로 해결 가능한지 검토합니다.
- 스타일 변형이 3개를 넘으면 컴포넌트 역할이 과도하게 넓은지 검토합니다.
- 예외 스타일은 디자인 백서 또는 Storybook 문서에 근거를 남깁니다.
- 작업실 UI 변경은 3D 뷰포트 면적과 프레임 예산에 미치는 영향을 함께 측정합니다.

## 11. 결론

CNC Render의 디자인은 공작기계의 외형을 흉내 내는 것이 아니라, 복잡한 가공 원리와 수치를 사용자가 통제 가능한 정보 구조로 바꾸는 데 목적이 있습니다. 전문성을 회색 입체 버튼, 금속 텍스처, 네온 효과로 표현하지 않고, 명확한 타이포그래피, 일관된 단위, 정돈된 패널, 신뢰할 수 있는 상태 피드백으로 표현합니다.

인터페이스는 라이트모드로 고정하고 장식성 렌더링을 최대한 배제합니다. 이를 통해 화면의 그래픽 예산을 공작물의 재료 제거, 공구 경로, 기계 운동학, 충돌 검증과 같은 핵심 3D 표현에 집중시킵니다. 결과적으로 CNC Render는 입문자에게는 단계적으로 이해할 수 있는 학습 환경을, 숙련자에게는 불필요한 시각적 방해 없이 수치와 공정을 다룰 수 있는 정밀한 웹 도구를 제공해야 합니다.
